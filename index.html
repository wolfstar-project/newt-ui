01
Installation

Install the CLI and add components directly into your project — same pattern as shadcn. No runtime dependency; components are copied into your codebase so you fully own them. 

# install the CLI
npx newt-ui@latest init

# add a component
npx newt-ui@latest add status-indicator embed slash-command

# list everything available
npx newt-ui@latest list
02
CDN jsDelivr

For static sites or quick prototypes, skip the CLI entirely and load the design tokens + component styles straight from jsDelivr. Two paths are available — the GitHub path works immediately after pushing, the npm path requires npm publish first. 

<!-- pinned to a release tag (recommended) -->
<!-- from GitHub (works immediately after pushing) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/newt-devs/newt-ui@main/registry/tokens.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/newt-devs/newt-ui@main/registry/components/button.css">

<!-- pinned to a release tag on npm (after npm publish) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@newt-devs/ui@0.1.0/registry/tokens.css">

<!-- pin to a specific git tag for stability -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/newt-devs/newt-ui@v0.1.0/registry/tokens.css">
03
Design tokens

Every component is built on CSS variables matching Discord's actual surface and accent colors, so themes stay consistent across light client, dark client, and AMOLED. Never hardcode a hex value — reference a --newt-* token.

--newt-brand · #5865f2 --newt-online · #23a55a --newt-idle · #f0b232 --newt-dnd · #f23f42 --newt-offline · #80848e

Using with AI
46
AI implementation guide

How to use newt/ui with AI tools — prompting patterns, wiring components to real bot data, and integrating newt-trace telemetry.

Pattern 1 — prompt Claude with the token file
You are building a Discord bot dashboard. Use only CSS classes
from the newt/ui component library. The available CSS variables are:
  --newt-bg-base, --newt-bg-surface, --newt-bg-elevated
  --newt-brand (#5865f2), --newt-online, --newt-dnd, --newt-idle
  --newt-text-primary, --newt-text-secondary, --newt-text-muted
  --newt-border, --newt-font-sans, --newt-font-mono

Generate only HTML using .newt-* class names. No inline styles.
No new CSS classes. No animations or transitions.
Pattern 2 — pipe newt-trace events into an embed
// newt-trace emits structured lifecycle events
const event = {
  type: "command.invoked",
  shard: 2,
  latency: 842,
  timestamp: "2026-06-13T14:23:00Z"
};

// Map directly to .newt-embed fields
renderEmbed({
  eyebrow: `newt-trace · shard ${event.shard}`,
  title: event.type,
  fields: [
    { name: "Latency", value: `${event.latency}ms` },
    { name: "Time",    value: event.timestamp }
  ]
});
Pattern 3 — newt-trace event stream → timeline
// newt-trace lifecycle stream → .newt-timeline
const dotVariant = (event) => ({
  "shard.connected":    "--success",
  "shard.disconnected": "--danger",
  "command.invoked":    "--brand",
})[event.type] ?? "";

events.map(e => `
  <div class="newt-timeline__item">
    <div class="newt-timeline__dot newt-timeline__dot${dotVariant(e)}">
    </div>
    <div class="newt-timeline__content">
      <div class="newt-timeline__title">${e.type}</div>
      <div class="newt-timeline__meta">shard ${e.shard} · ${e.timestamp}</div>
    </div>
  </div>
`).join("");
Pattern 4 — status from shard health → presence dots
// Map shard health to .newt-status__dot variants
const shardStatus = (shard) => ({
  "healthy":      "online",
  "degraded":     "idle",
  "disconnected": "dnd",
  "unknown":      "offline",
})[shard.health] ?? "offline";

// Use in .newt-member or .newt-server-banner
renderMember({
  name: `Shard ${shard.id}`,
  role: `${shard.guilds} guilds`,
  status: shardStatus(shard)
});
