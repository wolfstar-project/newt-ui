#### Check the aliases

`init` reads your aliases, it never writes them. `create-next-app` declares the
one that matters:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "paths": { "@/*": ["./src/*"] }
  }
}
```

#### Run init

<PmTabs cmd="newtui@latest init" />

layout already imports.

#### Put the root class on the body

```tsx title="app/layout.tsx"

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body className="newt-root">{children}</body>
    </html>
  )
}
```

## Server components \{#rsc\}

Nine components ship with a `"use client"` directive — the interactive ones:
modal, tabs, toast, reaction, spoiler, form-fields, permission, stage-banner and
token-field. The rest render on the server.

Answering yes to the React Server Components question at `init` keeps those
directives. Answering no sets `rsc: false` in
[`components.json`](/docs/components-json), and `add` strips them as it writes —
which is what a pages-router or client-rendered app wants.

## What init writes \{#written\}

```text
components.json                 the config, shared with shadcn
app/globals.css                 the --newt-* token block
lib/utils.ts                    cn()
components/ui/button.tsx        add button
```

See [Dark mode](/docs/dark-mode#next) for the theme toggle, and [RTL](/docs/rtl)
if the app has to run right to left.
