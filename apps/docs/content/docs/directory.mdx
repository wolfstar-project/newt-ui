`add` is not limited to this library. Anything published as a shadcn-compatible
registry installs with the same command, named by its namespace:

<PmTabs cmd="newtui@latest add @magicui/marquee" />

No configuration is needed for the registries below. A React project reads the
[shadcn/ui directory](https://ui.shadcn.com/docs/directory) and a Vue project
reads the [shadcn-vue directory](https://www.shadcn-vue.com/docs/directory);
which one applies is the `framework` in your
[`components.json`](/docs/components-json), so a namespace from one list does
not resolve in a project of the other.

<Callout>
  These registries are other people's code. newt/ui does not review, host or
  endorse them: read what a component does before you install it, the same as
  any dependency. `newtui view @registry/item` prints the source without writing
  anything.
</Callout>

## What happens on install [#install]

- **The item and what it depends on.** A third-party component names its
  dependencies bare — `button`, `card` — and means the shadcn component of that
  name, so those come from `@shadcn`, not from newt/ui. A file that already
  exists is kept, exactly as with any other `add`: your newt/ui `button` is not
  replaced unless you pass `--overwrite`.
- **Imports.** `@/registry/<style>/ui/…` and its siblings are rewritten to your
  aliases, the same way newt/ui's own sources are.
- **Colours.** These components are written against shadcn's colour names —
  `bg-primary`, `text-muted-foreground`, `border-border`. On Tailwind v4 the
  first third-party install appends one `@theme inline` block that points each
  of those at the `--newt-*` token playing the same part, so the component
  arrives wearing your theme and follows your [preset](/docs/create). On
  Tailwind v3 there is no stylesheet-level equivalent; the CLI says so and
  leaves the theme to your `tailwind.config`.
- **Nothing outside the project.** A registry chooses where its files go, so a
  path that is absolute or climbs with `..` is refused.

## A registry that is not listed [#custom]

Add it to `registries` in `components.json`. The value is a URL template with a
`{name}` placeholder; `{style}` is filled in as well when the registry uses it.

```json title="components.json"
{
  "registries": {
    "@acme": "https://acme.dev/r/{name}.json",
    "@private": {
      "url": "https://registry.example.com/{name}.json",
      "headers": { "Authorization": "Bearer ${REGISTRY_TOKEN}" },
      "params": { "version": "latest" }
    }
  }
}
```

`${NAME}` is read from the environment when the command runs, so a token never
has to be written into the file. An entry here wins over a directory entry of
the same name, which is also how you pin a namespace to a mirror.
