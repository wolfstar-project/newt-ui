A centred dialog with a header, a body and a footer, built on [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) in React and [Reka UI Dialog](https://reka-ui.com/docs/components/dialog) in Vue. The primitive owns the behaviour; newt/ui owns the look. It is the settings-panel shape from the client, so a form inside it looks like it belongs there.

## Examples

### With a form

Wrap the body and the footer in a form, so Enter in a field submits it. The field is the dialog's first control, which is where focus lands when it opens; the submit button stays disabled until there is a name.

<ComponentPreview name="modal" variant="form" />

### Close button

A dialog that only informs needs no footer. Position one `ModalClose` in the corner, outside `ModalHeader`, so its label does not become part of the dialog's accessible name.

<ComponentPreview name="modal" variant="close-button" />

### Long content

Cap `ModalBody` with a `max-h-*` utility and `overflow-y-auto` when the text can run long. The title and the actions then stay in view while the body scrolls.

`ModalTrigger` and `ModalClose` render a button. Pass `asChild` (`as-child` in Vue) to put the behaviour on your own element, such as a `Button`. Every part also accepts the native attributes of the element it renders, and a `className` that is merged rather than replaced.

## Accessibility

The dialog carries `role="dialog"` and `aria-modal="true"`, and closes on `Escape`. `ModalTitle` is its accessible name, so give it real text; `ModalDescription` is its accessible description. When it opens, focus moves to its first control, or to the dialog itself when it has none; a child with `autoFocus` keeps the focus it took. While it is open, Tab and Shift+Tab cycle through its controls and never reach the page behind, which the primitive also hides from screen readers and the overlay covers for the pointer. When it closes, focus goes back to the `ModalTrigger`.
