A text display is a block of message text, the most common Components V2 part. Put it in a `V2Container`, in a `SectionContent` or anywhere a message shows text. It keeps the line breaks of the string it gets (`white-space: pre-line`), so a bot's `\n` is a new line on screen.

## Sizes

`size` picks one of the chat markdown sizes. They match the `Markdown` component, so a text display and a rendered message look the same.

| `size`      | Markdown | Text                                     |
| ----------- | -------- | ---------------------------------------- |
| `default`   | none     | The container's size                     |
| `heading-1` | `#`      | 24px, bold                               |
| `heading-2` | `##`     | 20px, bold, the size of `SectionHeading` |
| `heading-3` | `###`    | 16px, bold                               |
| `subtext`   | `-#`     | 13px, muted colour                       |

Without a size, the text keeps the size and the colour of the container around it. A heading size keeps the font of the container, as a `Markdown` heading does. `SectionHeading` uses the display font and a tighter line height.

In Vue, a template collapses its own line breaks before the part sees them. Bind the text as a string, such as `{{ content }}`, to keep them. In the HTML version, start the text right after the opening tag; a newline there is a line break too.

The registry exports `TextDisplay` and `textDisplayVariants`. `TextDisplay` accepts the native attributes of the element it renders. React uses `className`, while Vue uses `class` and fallthrough attributes.

## Accessibility

A heading size only changes the look. If the text is a heading of the page, pass a heading element with `as`, such as `as="h3"`, so assistive technology can navigate to it. Keep the heading levels in order inside the page. Subtext uses `--newt-text-muted`; keep it for secondary text, never for the only copy of important information.
