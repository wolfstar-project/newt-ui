A whole assistant conversation, ready to wire to a model: who you are talking to, the exchange so far, and the composer. Before the first message the list gives way to a greeting and a few prompts to start from, and while a reply is on its way the assistant is shown writing.

The block is the arrangement, not a client. It calls no model and knows no transport: it draws the `messages` you give it and tells you what was sent. Calling the model, appending the reply (or growing it as it streams) and setting `pending` stay in your application, so it works with any SDK or none.

Send a message in the preview: the reply is canned and arrives after a pause.

## Usage

<Usage name="ai-chat" />

Keep the conversation in state, append the user's message when the block reports it, and set `pending` while your model answers. To stream, append the assistant's message once and replace its `body` as the text arrives; the block renders whatever the array holds.

## Accessibility

The conversation is a labelled, focusable scrolling region, so a keyboard user can reach it and scroll back through it. The writing state is a `role="status"` region named after the assistant, which screen readers announce without moving focus. The AI tag has an accessible name of its own ("AI assistant") rather than relying on the two letters. Say plainly somewhere in your product that the replies are generated: the tag marks who is speaking, it does not explain what that means.
