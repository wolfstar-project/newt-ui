A checkbox group is for several answers out of a visible list. Each option can have a description. For one answer out of the list, use a [Radio](/docs/components/radio) group.

Each option is built on [Radix Checkbox](https://www.radix-ui.com/primitives/docs/components/checkbox) in React and [Reka UI Checkbox](https://reka-ui.com/docs/components/checkbox) in Vue. The primitive owns the role, the keyboard and the form input. `CheckboxGroup` holds the list of checked values.

## Examples

### With descriptions

Give every option a `description` when the labels alone do not say what ticking them will do. This group is uncontrolled: it starts from `defaultValue` and keeps its own state.

<ComponentPreview name="checkbox-group" variant="descriptions" />

### Controlled

Hold the value yourself when something outside the group has to read or replace it. Here a count follows the selection and two [Button](/docs/components/button)s rewrite it in one step.

<ComponentPreview name="checkbox-group" variant="controlled" />

### Inline

The group is a flex column by default. For a few short labels, pass layout classes to lay the options out in a row that wraps.

`className` (React) or `class` (Vue) on `CheckboxOption` goes to the `<label>` around the row. Other attributes go to the checkbox button.

## Accessibility

The group has `role="group"`. Give it a `label` so a screen reader says what the options are for. Each option is a button with `role="checkbox"` and `aria-checked`. The button is inside a `<label>`, so the label text and the description are its accessible name, and a press on the text toggles it.

Each option is a tab stop. <kbd>Space</kbd> toggles the focused option. A focused option shows a 2px `--newt-text-link` outline. The check mark and the filled box show the state, so it does not depend on colour alone.
