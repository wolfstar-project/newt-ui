The Apps launcher, with search, a recents strip and the apps installed in a server. It is a popout on desktop and a bottom sheet on a phone. Compose it from the exported registry parts so local content and behaviour stay in the application while the visual contract stays token-driven.

The preview above is an `inline` launcher: it stays in the page and does not move focus. Without `inline`, `AppLauncher` is a dialog.

## Examples

### Bottom sheet

Pass `variant="sheet"` for a phone. The sheet fills the width, drops its bottom border and rounds its top corners. Its height is `--newt-app-launcher-sheet-height`, which defaults to `90dvh`. Set the property on the launcher or on an ancestor to change it.

Give `AppLauncherHandle` a `label` when the handle changes the sheet. It then renders a `button` with that name, so Enter and Space press it. Pass `expanded` to report the state as `aria-expanded`. Without a `label`, the handle is a decorative grip that assistive technology skips.

The example below is a `modal` dialog. Press the handle to change the height, type to filter the apps, and press Escape to close it. The search field is controlled: `value` and `onValueChange` in React, `v-model` in Vue.

<ComponentPreview name="app-launcher" variant="sheet" />

`AppLauncher` is built on [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) in React and [Reka UI Dialog](https://reka-ui.com/docs/components/dialog) in Vue. It renders in place, with no portal and no overlay, so your layout decides where it sits. It is open for as long as it is mounted.

When it mounts, focus moves to its first control. Tab cycles through the controls of the launcher. Escape calls `onClose` (`@close` in Vue). Unmount the launcher in answer. Focus then returns to the element that held it before.

Add `modal` when the launcher covers the page. The rest of the page is then out of use. Assistive technology skips it, focus cannot move to it, and a press on it asks to close the launcher.

### Drill-in view

A view that opens from an app has its own header. `AppLauncherHeaderTitle` takes the free width and centres in it. Put a spacer as wide as the back control after it, so the title sits in the centre of the header.

`AppLauncherPromoCard` draws a promoted app: art on top, a footer below. `AppLauncherItem` takes `trailing` for content after the text, such as a chevron. The item is a row that holds its button and, beside it, the trailing content. A press on a chevron presses the button. A control in `trailing`, such as a visibility toggle, keeps its own presses. `className` styles the row, and the ref and other props go to the button. `variant="tile"` puts the icon above the name, inside an `AppLauncherList` with `variant="grid"`.

An `<img>` in `AppLauncherItemIcon` or `AppLauncherRecent` covers the icon and is cropped. Pass `fit="contain"` for a logo that must not be cut, as the first tile does.

## Accessibility

Give the launcher a `label`. A dialog reads it when it opens. An `inline` launcher with a label is a `region` landmark; without one it is a plain `div`.

Tab cycles through the controls of a dialog, and Escape leaves it. A dialog that is not `modal` leaves the page beside it in use. Use `modal` for a sheet that covers the page, so focus cannot move to content the user cannot see.

Do not wrap a dialog `AppLauncher` in a [Drawer](/docs/components/drawer) or a [Modal](/docs/components/modal). That nests one dialog in another. Put an `inline` launcher inside them when you want their overlay.

A handle that changes the sheet needs a `label`, so it is a button with a name. Keep `expanded` in step with the sheet. A drag gesture alone fails keyboard users; the button gives them the same action.

`AppLauncherRecents` is a list, so a screen reader announces how many recent apps there are. Name it with `aria-label` or `aria-labelledby`, and give every `AppLauncherRecent` an `aria-label`. Label the search field, and keep `alt=""` on art and icons that the text beside them already names.

In the plain HTML and CSS distribution, `app-launcher.js` gives a launcher marked `data-newt-app-launcher` the same behaviour. A `data-newt-app-launcher-close` control closes it, and `aria-modal="true"` makes it modal. The launcher fires `newt:close` before it leaves the page; cancel the event to close it your own way.

With several launchers open, Escape closes the newest one that holds focus. An Escape that a control inside already handled with `preventDefault()` closes nothing, and the launcher marks the Escape it handles the same way. Tab skips controls inside hidden content.
