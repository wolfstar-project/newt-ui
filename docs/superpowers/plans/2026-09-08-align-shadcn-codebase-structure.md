# shadcn Codebase Structure Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Align the newt/ui app registries and CLI package layout with the current shadcn React and Vue repositories while preserving newt/ui's unified docs and CLI architecture.

**Architecture:** Registry source lives at each application root under `registry/bases/newt`, with generated loaders in root-level `__registry__`. The published `newtui` implementation moves to `packages/cli` and adopts the upstream CLI responsibility folders; compatibility wrappers move under `deprecated/` and keep their published names.

**Tech Stack:** pnpm 11, Turborepo, TypeScript, Next.js, Nuxt 4, Astro, React, Vue 3, Vitest, Oxc

**Spec:** `docs/superpowers/specs/2026-09-08-align-shadcn-codebase-structure.md`

## Global Constraints

- Keep package names, executable names, registry URLs, and `components.json` compatibility stable.
- Keep one shared Astro docs application and one multi-framework CLI.
- Keep React on Tailwind 3 and Vue on Tailwind 4 as compatibility fixtures.
- Keep generated registry JSON paths valid for the CLI's import transformer.
- Preserve all component source and metadata while moving directories.
- Update contributor documentation and local skills to the canonical paths.
